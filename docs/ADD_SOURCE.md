# 如何增加一个真实可用的数据来源

当前适配器是按网站明确配置的。这个项目没有“填任意 URL 就自动采集成功”的能力。继续开发时先验证来源质量，再写适配器。

## 1. 来源验收

对拟接入的公开栏目，保留入口 URL 和检查日期，确认以下事实：

- 列表能否访问，如何翻页，是否按最新发布或更新时间排列。
- 详情是否公开，采购主体是否明示，期限到底是报名、报价还是公示。
- 是否能看到物流服务范围和参加方式；是否只是中标历史、设备采购或广告。
- 是否有分页、重复发布、链接重定向、附件权限或网站访问频率要求。
- 页面中明示的公司，是实际采购方、代理、平台运营方还是建设单位。

公开可访问并不意味着内容字段完整。不能因能拿到 HTML，就标记来源“可产生有效商机”。至少抽查若干条详情，分别统计正文取得率、采购方可见率、期限可判读率和人工认可率。

## 2. 当前代码入口

| 文件 | 负责内容 |
| --- | --- |
| `collectors/sources.py` | 来源注册、URL 模板、列表与详情解析、条目选择 |
| `collectors/spider.py` | robots、域名边界、限速、预算、请求和错误状态 |
| `collectors/cli.py` | 独立采集进程的参数与 JSON 输出 |
| `radar/services.py` | 来源种子、队列、持久化、版本和工作流状态 |
| `radar/extraction.py` | 规则抽取、资格和期限判定 |
| `tests/test_collectors.py` | 小型合成网页夹具回归测试 |

新增来源时先修改注册表和解析器，新增静态站在 `collectors/extra_sources.py` 的 `CATALOG` 登记（由业务层自动种子化）；企业目录用 `radar/discovery.py` 的 `DIRECTORIES`。不要直接开放任意域名输入，也不要把需要登录的平台假设为公开来源。

## 3. 采集输出契约

```json
{
  "source_key": "registered_source",
  "status": "partial",
  "items": [{
    "external_id": "source-stable-id",
    "url": "https://source.example/notice/123",
    "title": "原文标题",
    "text": "可公开取得的正文",
    "html": "<html>原始页面</html>",
    "published_date": null,
    "listed_deadline": null,
    "kind": "procurement",
    "access_level": "partial",
    "attachments": [],
    "metadata": {}
  }],
  "next_cursor": 1,
  "stats": {"error_count": 0, "budget_limited": true, "coverage_complete": false},
  "error": ""
}
```

例子里的域名和内容为接口结构说明，不是一个已接入来源。真实条目必须来自可核实页面。

- `external_id` 应稳定，不要用每次抓取时间生成。
- `published_date` 只填网页明示的发布日期，不能借用报名开始或最后更新时间。
- `listed_deadline` 只有在列表中明示时才填；报名期限在 metadata 写 `deadline_kind=registration` 和原始 `deadline_raw`。
- 附件保存 `url` 和 `label`，不假设任何链接就是可下载采购文件。
- `partial` 可表示预算结束或已有成果但发生错误；依据 `stats.error_count` 区分。
- 没有得到正文时不能伪造空白“成功”记录；访问失败要保留原因和检查点。

## 4. 新来源测试顺序

1. 用一个真实公开列表和少量详情验证字段含义，记录 HTTP 和权限现象。
2. 创建不含整篇第三方内容的合成 HTML 夹具，覆盖正常页、空页、改版、被限制和附件情况。
3. 验证同一条重采不重复、更新不漏掉、预算中断可续跑、失败不推进错误检查点。
4. 每轮仅小批量真实试采，人工检查输出，确认后再启用定时。
5. 连续试用后按业务价值保留来源，不能只看采集条数。

## 5. 动态页面

如果来源确实必须运行 JavaScript，可在已有 Scrapy 适配器中接入 `scrapy-playwright`。先确认普通 HTML、RSS 或网站公开接口是否已经够用，避免每条公告都启动浏览器。需要安装项目的 `browser` extra 及匹配浏览器依赖；当前已接适配器均未依赖浏览器抓取；国义使用官网前端实际调用的公开 JSON 接口。

不要为抓取绕过验证码、会员权限或公司的网络限制。需要账户的来源应另做明确授权的导入/登录适配；不能在当前公开采集器里硬编码账户或 Cookie。

## 6. 从技术试用转为营业试用

建议下一轮按公司能承接的地区和服务类型，增加分行业/分区域采购栏目、园区企业变化公示、企业供应商招募页面。企业是否知名不作为准入条件。

每条待跟进记录至少复核：真正的采购法人、物流服务内容、有效参与期限、实际参加路径和适配原因。股权背景未知的企业先留池，不因无法自动判定日资就直接丢掉。

优先补上能取得完整需求的来源；若某聚合站大量记录只能读摘要，继续提升爬取速度无法补齐这一信息缺口。


## v0.2 两轮可复现验证

```bash
.venv/bin/python scripts/validate_sources.py --sources chinapost airchina --pages 10 --items 12 --output /absolute/new-validation-dir
```

输出目录必须不存在。先冻结范围与固定关键词，再按列表顺序两轮读取，第二轮传入已见 ID 并抽样刷新。保留预算中止、错误、匿名、历史和低相关记录。此命令不直接改业务库；正常入库使用 `manage.py run_once --source KEY`。完整交付验证索引见 `SOURCE_VALIDATION.md`，范围 A–E 分别冻结，后批不能覆盖首批分母。

合格来源须有可发现的栏目、至少 3 个真实详情、正文/实际采购角色和两轮分页或增量证据。HTTP 200、空配置、单篇转载、企业目录都不能代替需求来源验收。目录按企业单独统计；后台每批最多 30 家，记录轮转 offset，暂停企业不更新其证据。

## 公开请求安全（2026-11-14）

公开 HTTPX 和 Scrapy 请求必须走项目公共读取/中间件，所有合作进程共用同一锁；每次响应结束后至少间隔 1.1 秒，再进行下次公开请求。每个重定向目标均检查同协议 robots 和实际公网地址，robots 403/429/5xx、跳转或格式异常按不可用处理，404/410 按无 robots 文件处理；不要绕过验证码、登录或不允许的机器人规则。默认锁位于操作系统临时目录，不随数据目录变化；若配置 `LEAD_PUBLIC_RATE_DIR`，所有同时运行进程必须使用同一路径。浏览器和外部客户端不受此锁约束。新来源只有实际公开的至少三条详情及两轮采集证据完成后才能登记为验收来源，目录与需求来源分别统计。

招聘专题来源以可验证的列表企业名与独立详情对应为前提。来源明确的招聘企业记录在 `company`，但角色不标为采购人；每个岗位分别保留正文、出处和版本，发布时间缺失不能补猜。目录企业写入和岗位入库之间的检查点要在岗位处理成功后提交；中断重放必须幂等。页面无岗位或名单与详情不一致须记录并排除，不得计为可用详情。

官网招聘页如果没有逐岗 URL，应明确统计“不同岗位正文块”和“不同详情网址”两个口径，不将前者称为多个独立网页。若岗位正文未写法人，可用同一官网明示的企业介绍与职位页之间的链接核验，但证据摘录必须分别来自实际所在页面。集团目录或某个详情访问失败时，记录受影响的 URL；来源组成变化时不得盲目推进目录偏移量。

## 2026-11-14 高召回准入（覆盖上文旧门槛）

用户已确认：官方园区、日本商工会、外商投资协会的公开名单可直接按行入库，官网介绍只作可选增强；学校等非企业保留处理记录，分支与不完整名称单列。混合外资名录不整体算日企。新需求源完成一次真实列表与正文读取即可注册为**试用源**，保持定时关闭；三详情/两轮仍是后续验证项目，不再阻断入库。新证据使用 `directory_basis / identity_verification / japan_affiliation_basis / entity_type`，历史证据保留。

`collectors/japanese_public.py` 注册东风公开搜索、PERSOL公开JD搜索和广州环评词典过滤；由现有后台任务调用统一 public_fetch，列表POST也遵守robots、逐跳公网与限速。公开POST只用于网站本身的无登录搜索接口，不执行登录/注册/表单申请。搜索和详情证据hash写入SourceRun.stats.requests，备份携带相应raw文件。

目录每批最多50条；用名称规范化身份集合续跑，名单重排不跳条，原始行与处理结果可回查。日企动态词典在数据目录，`manage.py export_japanese_seeds` 可重建；恢复后也自动重建，词典不是人工股权确认。
